# Projects

A project is the top-level workspace for production planning. Generally, a project represents a single game.

<span id="components-and-workflows" />

## Components and Workflows:

Components represent the configuration that is built into directly into a game.
Usually, this is decided by the developers of the game, and you will copy the information into this tool.
The following are project components:

- Products
- Recipes
- Machines
- Modifiers
- Attributes

Conversely, Workflows represent the factory/world that you created in game. This is the core feature of this tool.

<span id="visibility" />

## Visibility

Projects can be private or public, which can be changed anytime.<br />
Other users cannot edit your project, even if the project is public.<br />
Workflows are always private, so users will never be aware of them.<br />

<span id="sharing-pattern" />

## Sharing Pattern

Public discovery is available through the explore page. Aliasing can be used to branch or mirror a project under another project identity.

For alias rules and expected behavior, see [Alias](/docs/projects/alias).
